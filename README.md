# 矿山尾矿库监测计划与异常处置审阅平台

基于Angular、Angular Material、NgRx、Angular Router、RxJS、HttpClient、MapLibre GL、Turf.js、Nx和TypeScript的独立前端工程。无后端时自动使用本地模拟数据，界面内操作保留版本和审计。

## 功能

- 位移、水位、渗流、降雨监测点，MapLibre测点图层和Turf巡检路线长度。
- 报警值、变化速率与阈值版本查看；中心发布新版本后相关异常**失效重算，已关闭异常也会重新打开**。
- **离线巡检批次（可恢复提交）**：山谷断网时记录复测值与现场证据；网络恢复后先与中心对账，再纳入原始读数、阈值版本和异常处置。
  - 同一测点同次读数两端分别修改时，**中心正式读数不被迟到离线副本覆盖**，双方值保留为“冲突待核对”，支持人工确认中心值或登记新的正式修订。
  - 现场证据逐个上传，失败保留检查点，刷新/崩溃后从断点续传重试。
  - 对账、合并、证据归档、阈值重算全部带幂等键，**重放不会多出审计记录**。
- 异常队列、现场复核、证据、复测评估和专业异议并存；阈值重算可使异常失效或把已关闭异常重开。
- 处置方案、重大异常应急联动、负责人审批和关闭条件校验。
- 原始读数只追加不修改，中心正式修订单独留痕。
- 总览、异常详情与JSON审阅包导出显示**同一批次、阈值版本与对账状态**（同一 selector 出数）。
- 状态快照持久化到 localStorage，模拟刷新后恢复提交检查点。

端口为`18462`。

```bash
npm install
npm run build
npm run dev
npm run verify   # 纯函数引擎+端到端不变量断言（21+6项）
```

## 离线对账演示路径

1. 打开“离线巡检对账”，批次 `OB-261006-01` 处于“失败待恢复”，EV-2/EV-3 证据待续传。
2. 点击“续传重试”上传证据（可先切到“链路中断”观察失败保留，再恢复链路）。
3. “与中心对账”：RD-1 出现冲突（中心正式值17.4mm vs 离线18.7mm），双方值保留；RD-4 中心值生效；S01 为新增读数。
4. “对账后合并入库”：阈值 T-D 离场基线 V4、中心已升 V5 → 已关闭异常 AN-260929-01 失效重算并重新打开；S01 新读数生成待复核异常；证据归档。
5. 再次点击对账/合并即为重放：审计、读数、异常数量不变。
6. 总览页可“发布新版本”调整阈值；审计页导出的审阅包与界面显示同一批次/版本/对账状态。
